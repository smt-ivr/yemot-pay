# yemot-pay

Cloudflare Worker שמשרת את מערכות ימות המשיח של כמה לקוחות (multi-tenant) מעל מסד D1 אחד (`yemot-pay`).
כל המערכת הטלפונית בנויה בימות המשיח. ה-Worker אחראי רק על:

1. **בדיקת גישה לקורס** לפי הטלפון המתקשר. אם אין גישה, מציע לרכוש או לצאת.
2. **הכנת הרכישה**: שני טלפונים לקורס, אישור, ומעבר לשלוחת הסליקה של נדרים פלוס.
3. **קליטת תוצאת התשלום** מנדרים פלוס:
   - הצליח: יש גישה, לצמיתות או לפי תוקף הקורס.
   - נכשל: אין גישה, ואפשר להיכנס לשלוחה שוב.
4. **מערכת ניהול** לקורסים, מוצרים, לקוחות, מנויים, הזמנות, תשלומים ויומן.

החיוב עצמו מתבצע בנדרים פלוס דרך ימות המשיח. אין חיוב חודשי.

כתובת: `https://smti.uk/yemot-pay/` (route ב-Cloudflare). מערכת הניהול נמצאת ב-`https://smti.uk/yemot-pay/admin/`.

## הקמה (חד פעמי)

```sh
# עמודת תוקף לקורסים (NULL = לצמיתות)
npx wrangler d1 migrations apply yemot-pay --remote

# סודות
npx wrangler secret put TENANT_KEYS      # {"zeevi-weiss":"<מחרוזת אקראית ארוכה, לפחות 16 תווים>"}
npx wrangler secret put ADMIN_PASSWORD   # סיסמת מערכת הניהול, לפחות 8 תווים
```

## הגדרות בימות המשיח

הכי פשוט: במערכת הניהול, בקורסים, פותחים קורס ולוחצים "הגדרת שלוחה", ומעתיקים.
בדוגמה: תוכן הקורס בשלוחה 5, הרכישה בשלוחה 6, הסליקה של נדרים פלוס בשלוחה 7.

**1. שלוחת תוכן הקורס (5)** – מוסיפים להגדרות הקיימות בדיקת הרשאה:

```ini
check_api=yes
check_api_every_entry=yes
api_link=https://smti.uk/yemot-pay/ivr/zeevi-weiss/check
api_add_0=key=KEY            ; המפתח של הלקוח מ-TENANT_KEYS
api_add_1=course=c1          ; קוד השלוחה / מזהה / שם הקורס
api_goto=/6                  ; מי שאין לו גישה עובר לשלוחת הרכישה
api_error_goto=/             ; בתקלה
```

השרת עונה `OK` למי שיש לו גישה, ו-`Out` למי שאין (עם `api_add_2=deny=no` יענה `NO`, ואז תושמע הודעת "אין הרשאה").

**2. שלוחת רכישה (6)**:

```ini
type=api
api_link=https://smti.uk/yemot-pay/ivr/zeevi-weiss/course
api_add_0=key=KEY
api_add_1=course=c1
api_add_2=pay=/7             ; שלוחת הסליקה של נדרים פלוס לקורס הזה
api_add_3=exit=/             ; לאן לצאת (ברירת מחדל: ניתוק)
```

השלוחה מציעה לרכוש (1) או לצאת (2), מבקשת שני טלפונים ואישור, ועוברת לסליקה. מי שכבר יש לו גישה שומע "כבר יש לך גישה" ויוצא.

**3. שלוחת הסליקה (7)**: שלוחת נדרים פלוס עם מחיר הקורס. כתובת לעדכוני תשלום (ראו למטה).

**מקור המחיר**
- בלי `price`: המחיר נלקח מהגדרות הקורס במערכת הניהול.
- עם `price=100`: המחיר נלקח מהשלוחה. אם הקורס לא קיים, הוא נוצר אוטומטית.
- אפשר לכפות מקור עם `source=db` או `source=params`.

**פרמטרים נוספים**
- `name`: שם לקורס שנוצר אוטומטית.
- `ok=/5`: בשלוחת הרכישה, מי שיש לו גישה יעבור ישר לתוכן במקום לשמוע הודעה.

**שלוחת מוצר / פגישה**: `/ivr/zeevi-weiss/product`, עם הפרמטרים `product`, `price`, `name`, `type=product|meeting|phone_meeting`, `pay`, `exit`.

## עדכון תשלום מנדרים פלוס

כתובת לעדכונים: `https://smti.uk/yemot-pay/pay/zeevi-weiss/nedarim?key=KEY`

התשלום משויך לרכישה הממתינה האחרונה של הלקוח לפי טלפון וסכום, או לפי הפניה מפורשת (`s123` / `o45`) אם נדרים מעבירה אותה.

> ⚠️ **שמות השדות של נדרים פלוס לא אומתו.** המיפוי נמצא ב-`src/payments/nedarim.ts`. כל עדכון נשמר ביומן עם הנתונים הגולמיים (ממוסכים), כך שאחרי עסקת ניסיון אחת אפשר לראות ביומן השיחות מה הגיע ולתקן.

## מבנה

```
src/
  router.ts           ניתוב (כולל התחילית /yemot-pay), זיהוי לקוח, אימות מפתח
  tenants.ts          רשימת הלקוחות המותרים: מזהה -> קידומת טבלאות
  db/                 שמות טבלאות מרשימה סגורה + שאילתות (הכל דרך bind)
  yemot/              פענוח בקשה מימות ובניית תשובות
  ivr/                שלוחת קורס, שלוחת מוצר
  payments/           מתאם נדרים פלוס + עיבוד תוצאת תשלום
  admin/              מערכת הניהול: עמוד, API, התחברות, הגדרת השדות שמותר לערוך
migrations/           שינויים במסד (להריץ עם wrangler d1 migrations apply)
test/                 בדיקות מול D1 מקומי עם עותק של הסכמה
```

## הוספת לקוח חדש

1. ליצור במסד את הטבלאות עם הקידומת החדשה (אותה סכמה, כולל `access_days`).
2. להוסיף שורה ב-`src/tenants.ts`.
3. להוסיף מפתח ל-`TENANT_KEYS`.

הלקוח יופיע בבורר הלקוחות במערכת הניהול.
