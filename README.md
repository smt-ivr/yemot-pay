# yemot-pay

Cloudflare Worker לרכישת קורסים ומוצרים בטלפון דרך ימות המשיח, עם סליקה בנדרים פלוס.
מערכת אחת לכמה לקוחות (זאבי וייס ואחרים), כל לקוח עם טבלאות משלו באותו מסד D1.

- כתובת: `https://smti.uk/yemot-pay/`
- מערכת ניהול: `https://smti.uk/yemot-pay/admin/`

## מה המערכת עושה

1. **בדיקת גישה** (`check_api` בשלוחת תוכן הקורס):
   - לטלפון יש גישה: התשובה `OK` והמתקשר ממשיך.
   - אין גישה: התשובה `Out`, וימות מעבירה לשלוחת הרכישה.
2. **רכישה** (שלוחת API):
   - הצעה לרכוש (1) או לצאת (2), שני טלפונים, אישור.
   - השרת עונה `credit_card=nedarim_plus,<סכום>,,1,1,,,<מספר מוסד>`, וימות מבצעת את הסליקה בנדרים פלוס.
3. **אחרי הסליקה** ימות קוראת שוב לשרת עם `CreditCard_CODE`:
   - `OK`: יש גישה, לצמיתות או לפי תוקף הקורס בימים, ומעבר לתוכן.
   - אחרת (כוכבית / `GoBack`): אין גישה, ואפשר להיכנס שוב.
4. **מערכת ניהול**:
   - לקוחות: יצירה, מפתח ומספר מוסד.
   - לכל לקוח: קורסים, מוצרים, רוכשים, מנויים וטלפונים, הזמנות, תשלומים ויומן שיחות.

## הקמה

רק סוד אחד: `npx wrangler secret put ADMIN_PASSWORD` (סיסמת מערכת הניהול, לפחות 8 תווים).

כל השאר מנוהל במערכת הניהול. בכניסה הראשונה ה-Worker יוצר בעצמו את טבלת הלקוחות, את הלקוח זאבי וייס ואת עמודת התוקף בקורסים.

## הגדרות בימות

במערכת הניהול, בלשונית **קורסים**, לוחצים **"הגדרת שלוחה"** ליד הקורס. ההגדרות מוצגות עם המפתח והקוד האמיתיים, מוכנות להעתקה.

**שלוחת הקורס** (למשל 5) – מוסיפים לשורות הקיימות:
```ini
check_api=yes
check_api_every_entry=yes
api_link=https://smti.uk/yemot-pay/ivr/zeevi-weiss/check
api_add_0=course=1
api_goto=1
api_error_goto=/
```

**תת-שלוחה 1 (רכישה, 5/1)**:
```ini
type=api
api_link=https://smti.uk/yemot-pay/ivr/zeevi-weiss/course
api_add_0=key=<המפתח מ"ניהול לקוחות">
api_add_1=course=1
```

**מהלך השיחה בשלוחת הרכישה**:
1. "אין לך מנוי לקורס X" או "תוקף המנוי שלך לקורס X הסתיים", ואז "לרכישה במחיר N שקלים הקישו 1, ליציאה הקישו 2".
2. "לשימוש במספר שממנו התקשרתם הקישו 1, למספר אחר הקישו את המספר וסולמית".
3. "להוספת מספר נוסף הקישו 1, להמשך הקישו 2", עד מספר הטלפונים שהוגדר בקורס.
4. מספר שגוי, מספר כפול, או מספר שכבר יש לו מנוי לקורס: המערכת מבקשת מספר אחר.
5. סליקה בנדרים פלוס.
6. "רכשת בהצלחה את הקורס X", ואם יש תוקף: "המנוי בתוקף ל-N ימים". חזרה לשלוחת הקורס (5).
7. ביציאה, או אם התשלום לא הושלם: חזרה לשלוחה שמעל שלוחת הקורס. אפשר לשנות עם `exit`.

**מוצר / פגישה**: `/ivr/zeevi-weiss/product`, עם `key`, `product`, ואופציונלית `price`, `name`, `type=product|meeting|phone_meeting`, `ok` ו-`exit`.

**מקור המחיר**:
- בלי `price`: מהגדרות הקורס במערכת הניהול.
- עם `price=100`: מהשלוחה. אם הקורס לא קיים, הוא נוצר אוטומטית.

**תשובות לימות**: תמיד בפורמט של ימות. בתקלה, למשל מפתח שגוי או מספר מוסד חסר, המתקשר שומע הודעה, והסיבה נרשמת ביומן השיחות.

## מבנה

```
src/
  router.ts      ניתוב (כולל התחילית /yemot-pay)
  tenants.ts     לקוחות הפלטפורמה: טבלת tenants, יצירה, מפתחות, הכנת המסד
  db/            סכמת טבלאות לקוח, שאילתות (שמות טבלאות מרשימה סגורה, ערכים דרך bind)
  yemot/         פענוח בקשה מימות ובניית תשובות (read, id_list_message, go_to_folder, credit_card)
  ivr/           check (בדיקת הרשאה), course, product, payment
  admin/         מערכת הניהול: עמוד, API, התחברות, הגדרת שדות
test/            בדיקות מול D1 מקומי
```
