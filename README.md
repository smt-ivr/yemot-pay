# ימות פיי

פלטפורמה למכירת קורסים, מוצרים ופגישות **דרך הטלפון**, עם סליקה בנדרים פלוס דרך ימות המשיח.
המערכת מנהלת כמה לקוחות (למשל זאבי וייס), וכל לקוח מקבל טבלאות משלו באותו מסד D1.

| | כתובת |
|---|---|
| מערכת ניהול / אזור אישי | `https://smti.uk/yemot-pay/admin/` |
| בדיקת גישה (check_api) | `https://smti.uk/yemot-pay/ivr/check?client=1&course=1` |
| רכישת קורס | `https://smti.uk/yemot-pay/ivr/course?client=1&course=1&key=...` |
| רכישת מוצר / פגישה | `https://smti.uk/yemot-pay/ivr/product?client=1&product=m1&key=...` |

`client` הוא **מספר הלקוח** שנקבע במערכת הניהול. כל הפרמטרים כתובים בתוך הכתובת עצמה, ואין צורך בשורות `api_add`.

📄 **תיעוד מדויק להעתקה לימות המשיח: [docs/YEMOT.md](docs/YEMOT.md)**. הגרסה עם הערכים האמיתיים נמצאת במערכת הניהול ← הגדרות ← הגדרות לימות המשיח.

## מדריך הקמה

### 0. פעם אחת ב-Cloudflare
- הסוד היחיד: `npx wrangler secret put ADMIN_PASSWORD`, הסיסמה של מנהל המערכת (לפחות 8 תווים).
- כל השאר מנוהל מתוך מערכת הניהול. בכניסה הראשונה המערכת מכינה את המסד בעצמה:
  - טבלאות הפלטפורמה.
  - הלקוח זאבי וייס, שמקבל מספר לקוח 1.
  - העמודות החדשות בקורסים.
  - טבלת טלפונים שמאפשרת יותר משני טלפונים לרכישה.

### 1. כניסה
נכנסים ל-`/admin/`. **מנהל המערכת**: משאירים את שם המשתמש ריק ומקלידים את `ADMIN_PASSWORD`.

### 2. מפתח Resend (למיילים)
בתפריט **ניהול הפלטפורמה ← הגדרות מערכת** מדביקים את מפתח ה-API של Resend (מתחיל ב-`re_`).
המפתח נשמר במסד, וממנו מוצגים רק 4 התווים הראשונים ו-4 האחרונים.

### 3. הגדרת הלקוח
בתפריט **לקוחות והרשאות** לוחצים על הלקוח ←
- **פרטים**: מספר לקוח, **מספר מוסד בנדרים פלוס**, איש קשר.
- **משתמשים והרשאות**: יוצרים משתמש לאזור האישי (שם משתמש וסיסמה), ולכל אזור בוחרים "ללא", "צפייה" או "עריכה".
  המשתמש נכנס באותה כתובת עם שם המשתמש שלו, ורואה רק את הלקוח שלו.
- **מפתח וכתובות**: המפתח (`key`) לשלוחות רכישה, ואפשרות ליצור מפתח חדש.

### 4. קורסים
בתפריט **קורסים ← חדש**. ממלאים:

| שדה | משמעות |
|---|---|
| שם, **מזהה קורס**, מחיר | המזהה מופיע בכתובות (`course=`) |
| תוקף גישה (ימים) | ריק = לצמיתות |
| כמה טלפונים לכל רכישה | כל מספר |
| פעיל | האם פתוח לרכישה |
| כשהקורס לא פעיל | "ממשיך לקבל גישה" או "נחסם, ושומע שהקורס אינו פעיל" |

### 5. השלוחות בימות
ליד כל קורס יש כפתור **"שלוחה"**. הוא מציג את ההגדרות עם המספרים והמפתח האמיתיים, מוכנות להעתקה.

**שלוחת הקורס** (למשל 5), מוסיפים לשורות הקיימות:
```ini
check_api=yes
check_api_every_entry=yes
api_link=https://smti.uk/yemot-pay/ivr/check?client=1&course=1
api_goto=1
api_error_goto=/
```

**תת-שלוחה 1 (5/1), רכישה:**
```ini
type=api
api_link=https://smti.uk/yemot-pay/ivr/course?client=1&course=1&key=המפתח
```

### 6. מה המתקשר שומע
1. נכנס לשלוחת הקורס. אם יש לו מנוי בתוקף, הוא ממשיך לתוכן.
2. אם אין לו, הוא שומע "אין לך מנוי לקורס X" או "תוקף המנוי שלך לקורס X הסתיים".
3. ההצעה:
   - עם תוקף: "לרכישת גישה לקורס למשך N ימים במחיר Y שקלים הקישו 1, ליציאה הקישו 2".
   - בלי תוקף: "לרכישת גישה לקורס במחיר Y שקלים...".
4. "לשימוש במספר שממנו התקשרתם הקישו 1 וסולמית, למספר אחר הקישו את המספר וסולמית".
   - 1 וסולמית: המספר שממנו התקשר, **בלי בקשת אישור**.
   - מספר שהוקש: "הקשתם 05…, לאישור הקישו 1, להקשה מחדש הקישו 2".
   - בדיקות: מספר ישראלי תקין, לא כפול, ובלי מנוי קיים לקורס. אחרת המערכת מבקשת מספר אחר.
5. "להוספת מספר נוסף הקישו 1, להמשך הקישו 2", עד המספר שהוגדר בקורס.
6. סליקה בנדרים פלוס (ימות). **עד שהתשלום מצליח לא נשמר כלום.**
7. הצלחה: נוצרים הרוכש, המנוי, הטלפונים והתשלום. המתקשר שומע "רכשת בהצלחה את הקורס X", ואם יש תוקף: "המנוי בתוקף ל-N ימים". אחר כך הוא חוזר לשלוחת הקורס ונכנס.
8. יציאה, תשלום שלא הושלם, או קורס לא פעיל: המתקשר תמיד שומע הסבר ויוצא לשלוחה שמעל שלוחת הקורס.

### 7. מוצרים ופגישות
בתפריט **מוצרים ופגישות ← חדש** בוחרים סוג: מוצר, פגישה או פגישה טלפונית. בימות:
```ini
type=api
api_link=https://smti.uk/yemot-pay/ivr/product?client=1&product=m1&key=המפתח
```
- בפגישה טלפונית המתקשר מתבקש גם טלפון לתיאום (1 וסולמית למספר שממנו התקשר, או הקשה ואישור).
- אחרי תשלום מוצלח נשלח מייל לפי ההגדרות.

### 8. מיילים
בתפריט **הגדרות ← מיילים**:
- **שם וכתובת שולח**: הכתובת חייבת להיות בדומיין שמאומת ב-Resend.
- **נמענים, וכתובת למענה.**
- **לכל אירוע** (פגישה, פגישה טלפונית, מוצר, קורס): הפעלה או כיבוי, נושא, תוכן, ונמענים נוספים.
- **משתנים** שאפשר לשים בנושא ובתוכן: `{product}` `{course}` `{price}` `{buyer_phone}` `{contact_phone}` `{phones}` `{validity}` `{date}` `{time}` `{reference}` `{client}`.
- **ברירת מחדל**: מייל על כל פגישה ופגישה טלפונית.
- **"שליחת מייל בדיקה"** שולח מייל עם נתוני דוגמה.
- כל מייל שנשלח או נכשל נרשם ב**יומן השיחות**.

### 9. בדיקה
בתוך מערכת הניהול יש עמוד **מדריך הקמה** עם אותם שלבים, וסימון ✓ ליד מה שכבר הוגדר. לבדיקה:
1. מתקשרים ורוכשים בסכום קטן.
2. ב**יומן השיחות** רואים כל שלב: `purchase_offer`, `payment_started`, `payment_success`, `email_sent`.

## אבטחה
- **הפרדה בין לקוחות**: שמות טבלאות נבנים רק מרשימה סגורה ומקידומת שנבדקת. כל ערך עובר דרך `bind`.
- **המפתח (`key`)**: שלוחות רכישה דורשות אותו, כי אליהן חוזר `CreditCard_CODE=OK` מימות.
- **בדיקת הגישה (`check`)**: לא דורשת מפתח, כי היא רק עונה אם יש גישה.
- **סיסמאות משתמשים**: נשמרות כ-PBKDF2-SHA256 (100,000 סבבים) עם salt. ההתחברות בעוגייה חתומה (HttpOnly, Secure, SameSite=Strict).
- **מחיקה או חסימה של משתמש** מנתקת אותו מיד.
- **שינוי `ADMIN_PASSWORD`** מנתק את כולם.
